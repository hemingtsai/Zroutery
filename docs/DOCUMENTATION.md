# Documentation Standard

> Authority: normative · Owner: docs · Last verified: 2026-11-14 · Verified by: `scripts/docs_check.py`

This file is the rulebook for every Markdown document in this repository. It is
short on purpose: a rulebook that needs its own rulebook is not a rulebook.

## Scope and precedence

- Applies to `AGENTS.md`, `CONTRIBUTING.md`, `README*.md` and everything under
  `docs/`.
- When two documents disagree, the higher row wins:

| Rank | Home | Answers |
|---|---|---|
| 1 | `AGENTS.md` | what an agent may do |
| 2 | `docs/development/verification.md` | which toolchain and gates are authoritative |
| 3 | `docs/development/architecture.md` | what the boundaries and invariants are |
| 4 | `docs/development/WORKFLOW.md` | how a commit and its evidence are formed |
| 5 | `docs/development/reference/*` | how one subsystem behaves |
| 6 | `docs/development/current-state.md` | what is true right now |
| 7 | `docs/archive/**` | what happened before; never current fact |

## Document types

Exactly one type per document. The type decides the required sections.

| Type | Purpose | Required sections | Forbidden |
|---|---|---|---|
| `entry` | agent entry | current state, non-negotiables, change matrix, verification pointer, stop conditions | background essays |
| `fact` | current facts, generated | gates, open issues, blockers, flaky, last green | hand editing |
| `normative` | rules and boundaries | scope, rules, canonical commands, change log, see also | unsourced facts, narrative |
| `guide` | onboarding and runbook | audience, prerequisites, steps, verify, troubleshoot, pointers | restating normative rules |
| `reference` | one subsystem | what it does, invariants, configuration, failure modes, not implemented, sources | plans and roadmaps |
| `adr` | durable decision | status, context, decision, consequences, sources | implementation diary |
| `record` | execution evidence | date, commit range, commands, results, what is not established | being cited as current fact |
| `index` | navigation, generated | legend, reading paths, tables, health | hand-written metadata |
| `historical` | archived document | an archive banner only | being edited to match new code |

## Metadata lives in one manifest

Every document's metadata lives in `docs/docs.manifest.json`; the document body
stays prose. `docs_check.py` fails when a Markdown file is in none of `docs`,
`pending` or `ignore`. `pending` is a visible migration state, not a permanent
home; its count must fall to zero before the migration is complete.

Every active `normative` and `reference` document starts with:

```text
> Authority: <type> · Owner: <backend|frontend|docs> · Last verified: YYYY-MM-DD · Verified by: <command or script>
```

Generated documents start with `<!-- generated by <script>; do not edit -->`.

## Source verification: facts are read, not remembered

- Every factual sentence in an active `normative` or `reference` document must
  be backed by a source read in the same change. Old documents are leads, never
  sources.
- Cite the defining symbol, not a line number alone:

```text
The default body limit is 32 MiB (`crates/zroutery-core/src/config/server.rs::ServerConfig::default_body_limit_mib`).
```

- Supported anchors: `path::symbol` (Rust item, test name, config key),
  `path::Key::subkey` (YAML/JSON key path), and `path#Lstart-Lend` as a fallback.
- A citation may cover a paragraph only when every fact in that paragraph comes
  from the cited symbols. Tables cite per row; lists cite per item.
- A number must come from a constant, a default, a script or a command result.
  An adjective that cannot be measured ("fast", "robust") is deleted.
- A "why" sentence links to an ADR or commit; it does not pretend to be code.
- A "must" sentence is normative and needs no source, but its rationale links to
  an ADR.
- `scripts/docs_sources.py --check` resolves every anchor. A document without a
  source anchor is not reference material; it is either a rule or it is deleted.
- A repository path written as inline code is a reference too: `docs_check.py`
  resolves it, or resolves it through the archive redirects.
- `scripts/docs_check.py` compares the source content hashes recorded in
  `docs/verified.json` with the current files. A changed source means the
  document must be re-read and re-verified. Strict mode: CI blocks.

## Audits and findings live in issues

- Audits, reviews, triage and risk discussions are GitHub Issues, not files under
  `docs/`.
- An audit that produces a decision writes an ADR; an audit that produces a
  durable fact updates a `reference` or `normative` document. Everything else
  stays in the issue.
- `current-state.md` links open issues; it never copies their findings.
- If an agent cannot read the issue tracker, it asks the user for the issue
  body. It does not guess a finding.

## Writing rules

1. One fact, one home. Normative documents link; they do not restate.
2. Commands are copy-pasteable; a placeholder must name the command that resolves
   it.
3. Absolute dates (`2026-11-14`), never "recently" or "currently".
4. Relative links, checked by `docs_check.py`; code fences carry a language tag.
5. Development documents are English. User documents are English, Simplified
   Chinese and Traditional Chinese, kept in sync. Archived documents keep their
   original language.
6. Historical documents are never rewritten to match new code; they are moved to
   `docs/archive/` and get one banner line. Paths are preserved through
   `docs/archive/redirects.json`.
7. No audit reports, plans or execution diaries are added to `docs/development/`.

## Size budgets

| Document | Limit |
|---|---|
| `AGENTS.md` | 150 lines |
| `docs/development/current-state.md` | 50 lines |
| `docs/development/verification.md` | 300 lines |
| `CONTRIBUTING.md` | 60 lines |
| `docs/DOCUMENTATION.md` | 200 lines |
| `docs/development/WORKFLOW.md` | 300 lines |
| `docs/development/architecture.md` | 400 lines |
| one `reference` document | 500 lines |

`docs_check.py` enforces these from the manifest.

## Change synchronization

Every change to code, contracts, gates, toolchain, configuration keys, wire
fields, release steps or process rules updates every affected document in the
same change.

- The affected set is computed by `scripts/docs_impact.py` from the documents'
  own source citations and the manifest triggers. It is not a memory exercise.
- If a document is required and did not change, CI fails. There is no
  `Docs-Impact: none` escape hatch; if a trigger is wrong, the manifest or the
  citation is fixed in the same change.
- Generated documents are regenerated, never hand-edited; CI compares the
  generated output with the committed file.

## Index and health

- `docs/INDEX.md` is generated from the manifest by `docs_check.py --write-index`.
- The index lists active documents, the pending migration set and the archive,
  plus the external issue entry points. It is not a list of issues.
- `docs_check.py` reports file counts, over-budget documents, unresolved links
  and pending documents.

## Review

- A document change is reviewed by the owner of the affected area.
- `AGENTS.md`, `verification.md` and `INDEX.md` are shared files: one author, one
  reviewer.
- Mechanical checks prove anchors resolve, links exist, sizes fit and sources did
  not move. They cannot prove an interpretation is correct. Every rewrite is
  spot-checked by a second reader on 3-5 factual sentences.
